# Messa

**Ближе. Даже на расстоянии.**

Самостоятельно размещаемый веб-мессенджер с русским интерфейсом, настоящим сервером и постоянным хранением данных. Первая рабочая версия **0.1.0**: не статичный макет и не обещание заменить Signal за один релиз.

## Запустить за минуту

Нужен **Node.js 24.14+ из ветки 24.x**. Установка npm-пакетов для запуска не нужна: у приложения **нет внешних runtime-зависимостей**.

```bash
git clone https://github.com/7w-yt1983-png/messa.git
cd messa
cp .env.example .env
npm start
```

Откройте **http://localhost:3000**. Создайте аккаунт, затем второй аккаунт в другом браузере / приватном окне. Найдите собеседника по `@username` и начните переписку. Сервер действительно доставляет сообщения между независимыми аккаунтами.

**Сначала посмотреть:** кнопка «Посмотреть демо» или `http://localhost:3000/?demo=1`. Демо изолировано от настоящих аккаунтов, не обращается к API и явно помечено как вымышленное. Демо-сообщения не сохраняются после перезагрузки.

> Важно: используйте именно адрес из `APP_ORIGIN`, без завершающего `/`. `localhost` и `127.0.0.1` — разные origin. Не открывайте порт разработки в интернет.

## Что работает

- Регистрация по имени пользователя, вход, выход и отзыв всех сессий.
- Личные чаты без дублей, группы до 32 участников, личное «Избранное».
- Обмен сообщениями в реальном времени между устройствами, присутствие и индикатор набора.
- Отметки прочтения, непрочитанные сообщения и восстановление после обрыва связи.
- Ответы с цитатой, редактирование, удаление своих сообщений для всех, реакции.
- Вложения до 10 МБ, просмотр PNG/JPEG/GIF/WebP, защищённая загрузка файлов.
- Поиск по чатам и тексту сообщений, включая кириллицу; постраничная история.
- Закрепление, архив, отключение уведомлений, переименование групп их создателем.
- Профиль, светлая / тёмная / системная тема, адаптация к телефону.
- Черновики и неотправленные сообщения в `sessionStorage` текущей вкладки; явный повтор отправки без дублей.
- Уведомления браузера по запросу пользователя, без текста сообщений. Работают только при открытом приложении.
- Клавиатура: `Ctrl/Cmd + K`, `Enter`, `Shift + Enter`, `Escape`; видимый фокус, подписанные кнопки, нативные диалоги.
- Устанавливаемая веб-оболочка там, где это поддерживает браузер. Service worker кэширует только публичные ресурсы, **никогда API, переписку или вложения**.

## Почему такой стек

**Browser ES modules + CSS / Node.js HTTP + SSE / SQLite WAL.**

Небольшой, понятный стек без обязательных SaaS, CDN, аналитики и платных ключей. Запись идёт через HTTP; обновления приходят по Server-Sent Events. После каждого переподключения клиент сверяется с сервером. SQLite — источник истины, а не оперативная память браузера. CSS разделён на слои и дизайн-токены.

Это сознательная архитектура для **одного процесса и небольшого закрытого сообщества**, а не распределённая система на миллионы пользователей. Подробности: [архитектура](docs/ARCHITECTURE.md), [безопасность](SECURITY.md).

## Проверка качества

```bash
npm run check
npm test
```

Проверяются реальные HTTP-запросы, права доступа, CSRF, сессии, конкурентная идемпотентность, Unicode-поиск, прочтение, вложения, SSE и сохранность после перезапуска. Для браузерных сценариев нужен отдельно установленный Playwright:

```bash
npm install --no-save --package-lock=false playwright@1.63.0
npx playwright install chromium
# В другом терминале: npm start
npm run test:e2e
```

Браузерная проверка использует два независимых аккаунта, проверяет отправку, ответы, реакции, файлы, XSS, поиск, черновики, повтор после офлайна, темы и телефон. Скриншоты появляются в `artifacts/`. Тестовые аккаунты создаются в указанной базе: **не запускайте E2E на рабочем сервере**.

GitHub Actions настроен для автоматической проверки. Статус удалённого CI надо смотреть во вкладке **Actions**; локальная проверка не заменяет подтверждение его запуска.

## Развёртывание и данные

[Инструкция по HTTPS, Docker, бэкапам и восстановлению](docs/DEPLOYMENT.md).

- По умолчанию данные находятся в `data/messa.sqlite` и `data/uploads/`.
- `.env`, база, вложения, бэкапы и пользовательские данные исключены из Git.
- Production требует HTTPS. Публичная регистрация по умолчанию закрыта; для открытия нужен приватный код приглашения.
- Код в репозитории **не означает**, что сервис уже опубликован в интернете. Нужны домен и сервер.

## Честные ограничения версии

**Нет сквозного шифрования.** Администратор сервера имеет доступ к сообщениям и файлам. HTTPS защищает транспорт, а не данные от владельца сервера.

Пока нет звонков, голосовых сообщений, push-доставки при закрытом браузере, почтового восстановления пароля, MFA, блокировок/модерации, изменения состава групп и удаления аккаунта через интерфейс. Поиск — по тексту, не по содержимому файлов. «Прочитано» означает прочтение хотя бы одним другим участником, не всеми. Архив возвращается при новом сообщении. Уведомления и PWA зависят от браузера.

Не называем эту версию прошедшей внешний аудит безопасности, проверку больших нагрузок или готовой к публичному массовому запуску. Следующие этапы и критерии готовности: [дорожная карта](docs/ROADMAP.md).

## Структура

```text
public/       интерфейс, демо, темы, защищённая веб-оболочка
server/       HTTP API, безопасность, SQLite, события
scripts/      проверки и резервное копирование
tests/        unit / HTTP integration / browser E2E
.github/      автоматические проверки и шаблоны для разработки
docs/         архитектура, эксплуатация, развитие
```

Внешние библиотеки не скопированы в исходники. Лицензию на публикацию и повторное использование выбирает владелец репозитория; до этого отдельная open-source лицензия не заявляется.
